# 2026-10-20 — M2 to M5 built offline: what was built, what broke, what is still unproven

*Drafted by Claude Code in one long session at the owner's request ("one shot m2-5, we will do the gate checks after"). Nothing here is a measured result: no model was called. The gates for U9 to U13 are still owed (see LEARNING.md).*

## What exists now
- **M2:** cassettes in `src/` (U10), budget guard that refuses anything not provably free (U9), a trace writer, CLI `plan`, `add-price`, `smoke`, `run`, `report`, `survival`. The exit test records a run through cassettes and replays it: the two traces are byte-identical except `cassette_hit`.
- **M3:** four policies, five invariants as property tests, ADR-019.
- **M4:** two canary packs, a two-sided grader, exact McNemar, paired bootstrap, Benjamini-Hochberg, a resumable runner, analysis that refuses to mix simulated and recorded rows, a simulated agent (labelled, never measured), a deterministic survival grid and its site page, ADR-020, drafts of EXP-001/002/003.
- **M5 (partly):** `check_claims.py` in CI against `docs/claims.json`, CI now runs the design tests, the site build and an export-drift check, threats to validity extended.

## What broke on the way (failures stay in the notebook)
1. **Survival was scored at the wrong moment.** The first version judged "is the rule still in the window" at the end of the trace. The agent's own reply repeats the channel it chose, so a forgotten rule scored `kept`. Found by a test that made the simulated summarizer drop the rule on purpose. Now judged on the window the probe call saw, excluding the probe (the probe also lists the real channel). Recorded in ADR-020.
2. **`probe_step` went stale after length-matching trimmed turns**, so the probe message could not be found. Fixed where the trim happens; a test pins it.
3. **`length_matched` keys collided across policies.** With two policies in one experiment the second policy's twin was skipped as "already done" and would have been sized from the wrong treatment. `length_matched` now names its policy; a test runs two policies and checks each twin was sized from its own treatment.
4. **My EXP-003 draft stated something the data contradicts.** I wrote that `head_tail` keeps a rule planted at turn 0 or 1 at every budget. The grid says turn 1 is lost at 1200 tokens (0 of 20). Caught only because I looked up the cells before registering the claim. The draft now says so, and every survival number in the drafts is registered in `docs/claims.json` so CI would catch the next one.
5. **Windows:** a model id like `x:free` is not a valid directory name; cassette directories now use a safe slug. Heredocs in this environment mangled regexes and backslash continuations twice; those files were rewritten with the editor tools instead.
6. **A budget-stop test expected the wrong count.** The treatment episode needs two calls (summary and probe); a stop on its second call leaves no half-written row, so two episodes finished, not three. The code was right; the expectation was wrong.

7. **The bootstrap interval and the exact test disagreed at n=10.** Running the simulated pipeline end to end gave 4 discordant pairs against 0: a paired bootstrap interval of +10% to +70% (excludes zero) but an exact McNemar p of 0.125. My first interpretation rule in EXP-001 trusted the interval alone, which would have called that a replication. The rules in EXP-001, EXP-002 and EXP-003 now require both the interval and the adjusted exact test. This came from watching the toy pipeline, before any real data existed, which is what it is for.

## What this does not show
- No model has been called. Every `simulated` row comes from a toy agent that follows a rule if it can read it, so it exercises the pipeline and says nothing about models.
- The deterministic grid is mechanical: it tells you what a policy keeps from a synthetic history, not what an agent does afterwards.
- Which free models call tools reliably is unknown until `ctxcheck smoke` has been run by the owner with a key.
- Whether Groq, Gemini, NVIDIA or Mistral accept `parallel_tool_calls: false` is still unverified; the option is off in every preset.
- The browser re-application of policies to a recorded run (M3 stretch) was not built: it needs a recorded run to be worth showing, and it is listed under Later in the roadmap.
